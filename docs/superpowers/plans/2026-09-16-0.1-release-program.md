# Parquet.SourceGenerator 0.1 Release Programme Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resolve the substantive safety, functional, API, compatibility, and release-process gaps required to make a defensible `0.1.0` release decision.

**Architecture:** Work is split into independently landable issue-sized PRs. Safety validation is emitted at the generated-reader boundary before allocation or decoding; API work is governed by the existing emitted, shipped, and internal seam catalogues; release evidence is generated by the repository’s existing verification scripts and workflows.

**Tech Stack:** C# source generators, Roslyn incremental generators, Parquet.Net 6.x and V4/V5 legacy APIs, xUnit/Shouldly, CSharpier, Native AOT, GitHub Actions, and C#-based repository scripts run with `dotnet run`.

**Spec:** `docs/04-ROADMAP-AND-CONTRIBUTING.md`, `docs/07-KNOWN-LIMITATIONS.md`, `docs/18-API-CHANGE-CONTRACT.md`, and GitHub issue [#230](https://github.com/rtkelly13/Parquet.SourceGenerator/issues/230).

## Global Constraints

- All work occurs in `/temp/` worktrees; the primary checkout is never changed.
- All pull requests target `main`, use conventional commit titles, and merge by squash only.
- Both modern and legacy emitters are covered whenever the selected issue promises both backends.
- No public or generated API member is added or removed without its catalogue entry and `docs/api/LEDGER.md` entry.
- Safety failures use deterministic `InvalidDataException` diagnostics and are tested against malformed input.
- Repository tooling is authored in C# and invoked with `/Users/ryankelly/.dotnet/dotnet run` or `dotnet tool run`.
- Every issue is checked in the local root `TODO.md` only after implementation, evidence, documentation, and PR resolution are complete.
