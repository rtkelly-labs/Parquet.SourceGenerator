## 2. Critical path and parallel lanes

```text
#489 -> #576 (+ #369 lease) -> modern trims (#584, #512, #585/#586/#587)
     -> #600 BackendProfile plumbing -> #494 legacy reader/pruning/parallel
     -> #495 + #601 legacy writes and batches -> #619 legacy nested (XL) + #620 legacy Arrow (L)
```

Legacy parity is on the critical path of 0.1. Base plan: 6-9 weeks elapsed, plus 4-6 weeks for nested
(#619) and 2-3 weeks for Arrow (#620), so roughly 12-18 weeks for legacy parity alone, gated mostly by
owner review of several breaking PRs. Everything else in sections 1 and 4 fits inside that window if it
runs in parallel.

## 5. Decisions

### 5.1 Legacy-parity decisions (owner, 2026-10-02; recorded in #582)

1. Scope: flat surface, nested types (#619) and the Arrow bridge (#620) are inside the gate. Doc 47 section
   7 and docs/42 are amended by #621. The permanent-deviation list shrinks to win-x86 compressed writes,
   net472 `LangVersion` 7.3, per-column encoding hints and `ByteSplitStream`, the `SmallestSize` fallback
   below net6, and `MaxStringLengthBytes` validating after materialisation.
2. 0.0.x legacy users break with no shims: modern names, flat reads removed, `IReadOnlyList` widened to
   `IReadOnlyCollection`; ledger entry and CHANGELOG migration table (#604, #594).
3. Two packages; #496 moves to `post-0.1`; the `Parquet.SourceGenerator.Legacy` id stays; a version guard
   diagnostic (#605) replaces single-package selection and covers the CS0101 collision of #462.
4. Trim modern first (#584, #512); #492 moves to `post-0.1` (strategy C, #600); #493 and #494 stay v0.1
   Blockers.
5. Legacy `Batches` is implemented (#601); doc 49's permanent exclusion goes.
6. Minimum Parquet.Net 4.25.0; claim 5.x only after its CI row passes (#599).
7. Package id unchanged.
8. Legacy hostile-input hardening (#362) first.
